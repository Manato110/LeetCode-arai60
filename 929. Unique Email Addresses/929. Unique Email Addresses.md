例を見る限り、  
 - 注目したいのは`@`より前の部分だから、`@`より後ろは見なくて良さそう
 - `@`より前の部分では、以下のルールが適応される
   - `.`はついてない場合のものと同一視してよい = 消しても大丈夫そう  
   - `+`とそれより後ろの部分はついていない場合のものと同一視してよい = これも消して大丈夫そう

&nbsp;  
ルールをまとめたところで、解法が思いついた  
 - ひとつずつ入力リストの要素を見ていき、上のルールを適応し削除できるところは削除する
 - 最終的に得られた文字列が、今まで見た文字列でないなら、セットに格納
 - 最後にセットの長さを返す

&nbsp;  
ルールを適応し削除するところは、恐らく正規表現を使うの良いのかな...？  
文法を全然覚えていないので、正規表現での解法は断念  
&nbsp;  
`explanation`にあったように、セットに格納するのは`@`以降も含むメールアドレス全体であっておきたい   
単純に`@`以降を削除することはしないようにしたい  
&nbsp;  
解法を少し修正する  
`.`より先に`+`以降の文字列を削除したほうが、確認する文字列長を短くできる  
 - 入力リストの要素`email`を`@`で区切り、`local`と`domain`とする
 - `local`について...
   - 前から見て最初に現れる`+`で区切り、手前のみ残す 
   - `.`を削除する
 - 整形した`local`と`domain`を結合したものが、今まで見た文字列でないなら、セットに格納
 - 最後にセットの長さを返す

&nbsp;  
文字列の分割は`split`関数、削除や置換は`replace`関数で行える    

実際にコードを書く

### 書いたコード1
```python
class Solution:
    def numUniqueEmails(self, emails: List[str]) -> int:
        unique_emails = set()

        for email in emails:
            local, domain = email.split('@')
            local = local.split('+')[0]
            local = local.replace('.', '')
            reshaped_email = local + '@' + domain
            unique_emails.add(reshaped_email)
        
        return len(unique_emails)
```
AC  
時間計算量：`O(N*L)`
            入力リストの各要素について、`@`で分割、`+`, `.`で削除を行っている  
            要素の文字列を探索しておこなうため、それぞれ要素の長さ`L`に比例する  
            要素数`N`と、平均した各要素の長さ`L`だけかかるので、`O(N*L)`
空間計算量：`O(N)`入力リストの長さに比例する

実際にメールアドレスのチェックがおこなわれるときを想定すると...  
`local`部分にも`@`が利用できるので、`local`と`domain`の分割は一番右側の`@`でおこないたい  
⇒ `rsplit`関数で実装可能  
`local, domain = email.rsplit('@', 1)`  

メールアドレスとして不適切なものが混じっていたときに、どう対処するのか？  

 - 検出したらその時点で実行を中断し、エラーメッセージを出力する  
 - 検出したら、そのメールアドレスはスキップし有効なメールアドレスだけ考慮した結果を出す

利用場面によってどちらの場合も考えられる  
(例えば、前者なら、結果をもとに入力のリスト自体を編集するような場合  
後者なら、通信においていちいち無効なメールアドレスに引っかかって、エラーで止まることをしたくない場合)  
メールアドレスが有効なものかを判断する部分をコードに組み込んでみる  

有効なメールアドレスの条件 
 - 長さ256文字以下  
 - `@`が一つ以上含まれている    

本当はもっと厳格な国際標準があるが、簡単のため上の二つをチェックする  
参考：https://www.onamae.com/server/rs/server-guide/mail/page-rule/  

不適切なメールアドレスがあったら即実行を中断するパターンを書く  
### 書いたコード2
```python
class Solution:
    def numUniqueEmails(self, emails: List[str]) -> int:
        unique_emails = set()

        for email in emails:

            if len(email) > 256:
                raise ValueError("This address exceeds length limit")

            if '@' not in email:
                raise ValueError(f"{email} is not a valid email address")

            local, domain = email.rsplit("@", 1)
            local = local.split('+')[0]
            local = local.replace('.', '')
            normalized_email = local + '@' + domain
            
            unique_emails.add(normalized_email)
        
        return len(unique_emails)
```
微修正点として、整形後のメールアドレスを、正規化したということで`normalized_email`にした  

次に、検出したら、そのメールアドレスはスキップし有効なメールアドレスだけ考慮した結果を出す方も考える  
`try-except`で、エラーが出たらスキップすることを`print`する

### 書いたコード3
```python
class Solution:
    def numUniqueEmails(self, emails: List[str]) -> int:
        unique_emails = set()

        for email in emails:
            try:
                if len(email) > 256:
                    raise ValueError("This address exceeds length limit")

                if '@' not in email:
                    raise ValueError(f"{email} is not a valid email address")

                local, domain = email.rsplit("@", 1)
                local = local.split('+')[0]
                local = local.replace('.', '')
                normalized_email = local + '@' + domain
                
                unique_emails.add(normalized_email)
            
            except ValueError as e:
                print(f"Invalid email skipped: {e}")
                continue
        
        return len(unique_emails)
```
