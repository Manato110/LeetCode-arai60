## Step.0
まずは自力で解く  
問題の理解から  

前問(House Robber)より、  
 - 家は円状に連なっているため、最初の家と最後の家は隣接している
   
という条件が追加されている  

基本的な解法は、前問の応用で行けそう  
前問での解法  
最後に見た家で盗みを働いたか`robbed_last`と、働かなかったか`skipped_last`で  
金額が最大となる場合を保持しながら更新していく  

異なる部分は、最初の家と最後の家両方で盗みを働くことはできないということ  
なので、はじめから片方を削除して、  
 - 最初の家を抜きに、(`nums[1:]`)で最大金額を考える`max_money_considered_without_first`、
 - 最後の家を抜きに、(`nums[:-1]`)で最大金額を考える`max_money_considered_without_last`、

これら2つの値で最終的に`max`を取ったものが求める値になる  

発想としては、分割統治法的なアプローチといえるのかな  
主問題を2つの問題に分割して、最後にそれらを統合している  

なんとなくだけど、自分にはこの考え方で解き始めようとする癖がある気がする  
とりあえず難しそうな問題は分割できないかな...という感じ  
これが逆にノイズになる場合もあるはずなので、そのときにどうしたらよいか  
やっぱり、得意な道具を1つもっているのは心強いが、  
ゆくゆくはいろんな道具から最適なものをすぐに引き出せるようになりたい  

もう一つ、最初の家で盗みを働いたかどうかの情報を保持して、それをもとに最後の家で盗みを働くかを決める方法  
少し検討したが、最初の家で盗むか・最後に見た家で盗むかで2×2で4通りの状態を保持する必要があると思い、やめた  
さすがに一つ目のアプローチの方が、すぐに実装できると思った  

時間計算量としては、入力の長さを`N`として、  
2つのfor文で、合計`2 * (N - 1)`回の処理を行っているので、`O(N)`  
空間計算量としては、値を保持する`robbed_last, skipped_last`等について、全て一時変数であり、入力の長さに依存しない  
よって、`O(1)`  

時間計算量`O(N)`で、Nが最大100であるなら、まあ`TLE`にはならないだろう  

似た構造が2か所あり、冗長に感じたので、関数として作成する場合も作る  
要素が1つしかないとき、最初の家 = 最後の家となってしまうので、要素は非負より、この時だけ`nums[0]`を返す  

### 書いたコード 1
```python
class Solution:
    def rob(self, nums: List[int]) -> int:
        if len(nums) == 1:
            return nums[0]

        robbed_last = 0
        skipped_last = 0

        for num in nums[1:]:
            temp_robbed_last = robbed_last
            robbed_last = skipped_last + num
            skipped_last = max(skipped_last, temp_robbed_last)
        max_money_considered_without_first = max(robbed_last, skipped_last)

        robbed_last = 0
        skipped_last = 0

        for num in nums[:-1]:
            temp_robbed_last = robbed_last
            robbed_last = skipped_last + num
            skipped_last = max(skipped_last, temp_robbed_last)
        max_money_considered_without_last = max(robbed_last, skipped_last)

        return max(max_money_considered_without_first, max_money_considered_without_last)
```

```python
class Solution:

        skipped_last = 0

        for num in nums:
            temp_robbed_last = robbed_last
            robbed_last = skipped_last + num
            skipped_last = max(skipped_last, temp_robbed_last)
        return max(robbed_last, skipped_last)
```

両者に共通しているのは、どちらもDPで用いられる、過去に解いた問題の答えを保持する方法  
ただ、取り掛かる問題の順番が違う  

tabulation 
 - ボトムアップ
 - iterativeに、0番目から目的の番まで計算する
 - 時間計算量：`O(N)`
 - 空間計算量：`O(1)`　直前の値を保持すれば十分である（それより前の値は忘れても大丈夫なため）
 - memoizationと比較すると、実装が困難なことが多い
 - 複雑性ボーナスがある(iterativeなので、recursiveと比較して計算量の見積もりがしやすい)

memoization 
- トップダウン
- recursive、目的の番のものを計算するために、一つ前の計算をして..を繰り返し、値が分かるところまで戻ってから目的の番を計算する
- 時間計算量：`O(N)`
- 空間計算量：`O(N)`
- tabulationと比較して、実装しやすいことが多い(その代わり可読性が低くなったり、デバッグが大変になりやすい)
- 一部の分割問題さえ解ければ十分な場合は、memoizationの方が実行が早く終了する
- そうでないときは、関数の再起呼び出しの分だけオーバーヘッドが発生する

今後も読まれるコードを書くという観点では、なるべくtabulationで書いた方が良いのだろう

```python
class Solution:
    def rob(self, nums: List[int]) -> int:
        length_nums = len(nums)
        if length_nums <= 3:
            return max(nums)

        max_money_considered_without_first = self.max_robbed_money(nums, 1, length_nums - 1)
        max_money_considered_without_last = self.max_robbed_money(nums, 0, length_nums - 2)

        return max(max_money_considered_without_first, max_money_considered_without_last)
    
    def max_robbed_money(self, nums: List[int], left: int, right: int) -> int:
        robbed_last = 0
        skipped_last = 0

        for i in range(left, right + 1):
            temp_robbed_last = robbed_last
            robbed_last = skipped_last + nums[i]
            skipped_last = max(skipped_last, temp_robbed_last)
        return max(robbed_last, skipped_last)
```
