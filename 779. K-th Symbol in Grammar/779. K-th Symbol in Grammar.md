## Step.0
まずは自力で解く  
問題の理解から  

We build a table of n rows (1-indexed).   
We start by writing `0` in the 1st row. Now in every subsequent row, we look at the previous row and replace each occurrence of `0` with `01`, and each occurrence of `1` with `10`.  

For example, for n = 3, the 1st row is `0`, the 2nd row is `01`, and the 3rd row is `0110`.  
Given two integer n and k, return the kth (1-indexed) symbol in the nth row of a table of n rows.  

Constraints:
```
1 <= n <= 30
1 <= k <= 2n - 1
```

`0`の数字列(`row0`と呼ぶ)からスタート  
`0`を`01`、`1`を`10`に置き換える操作を行う  
`n`操作後の列を`row n`とする  
`row n`の先頭から`k`番目の数字が`0`か`1`かを答える  

まず考えたのは、`row n`を実際に作ってみること  
ちょっと実験  
`row`  
`1`　`0`  
`2`　`01`  
`3`　`0110`  
`4`　`01101001`  
`5`　`0110100110010110`   
同じような並びが続いている  
規則性としては、`row n`と`row n+1`について  
`row n`の`0`・`1`を反転(ビット反転)した列を用意して(`reverse row n`と命名)、  
`row n`を2^(n-1)桁左にシフトしたものを足し合わせると`row n+1`になる  

ただ、律儀に`row n`を作ろうとすると、  `n`が最大30という制約から、  
`row n`の長さは最大で`2^(n-1) = 2^29`  


 ただ、ビット反転演算子として`~`があるが、pythonでは上の桁が無限に0で埋められているという設定になっているらしい  
 (参考：https://qiita.com/7shi/items/41d262ca11ea16d85abc)  
 なので、例えば`01`を`~`でビット反転させると、  
 `0 ... 0001` ⇒ `1 .. 1110 = -2`となり、意図した形にならない  

 なので、`row n`と同じ長さで値が各桁全て1`1 ...1`のビットマスクを作り、これとのXORで反転させる  
 これらをまとめると、  
 - ビットマスクを作成   
 - XORでビット反転
 - 同じ桁だけ左シフト
 - 加算

これをn回行うことになる、それぞれ定数時間で実行できるので、`O(n)`で`row n`を作れる  
先頭から`k`番目 = 末尾から`n - k`番目を求めるには、  
`row n`を`n - k`桁右にシフトして、`1`とのANDで求めることが出来る。  

コードに起こす  
### 書いたコード 1
```python
class Solution:
    def kthGrammar(self, n: int, k: int) -> int:
        row = 0
        
        for i in range(1, n):
            row_length = 2 ** (i - 1)
            mask = (1 << row_length) - 1
            reversed_row = row ^ mask
            row <<= row_length
            row += reversed_row
            
        total_length = 2 ** (n - 1)
        shift_length = total_length - k
        
        return (row >> shift_length) & 1
```
計算量について、  
一番ネックになると考えられるのは、ビットマスクとのXORの部分、ほかは定数時間でできる  
`row_length`がループを回すごとに2倍になり、1, 2, 4, ... , 2^(n - 2)まで  
それぞれの長さの場合で、ビットマスクとのXORを計算しており、これは`row_length`の長さだけかかる  
よって全体だと`1 + 2 + ... + 2^(n - 2) = 2^(n - 1) - 1 = O(2^n)`  
これはまずい  
空間計算量も、最終的に`2^(n - 2)`の長さのマスクと列を保持するから、`O(2^n)`
ACだが、実行時間7085ms, 使用メモリ268.29MBで最低クラス  

やっぱり、`row n`を直接求めるのは時間がかかる、うすうす気づいてはいたが...   
ただ、実際にやってみた意味はあったとは思う  

とはいえ、ここからどう改善しようか  

後気づいたこととして、先頭から要素を見ていったときに、`row n`において先頭から`k`番目の要素が存在するとき、  
`row n+1`以降もずっとその値のままであるということ  

つまり、`row`の長さが`k`より大きくなるところまで考えれば十分  
### 書いたコード 2
```python
class Solution:
    def kthGrammar(self, n: int, k: int) -> int:
        if k == 1:
            return 0
            
        row = 0
        current_length = 1
        
        for i in range(1, n):
            row_length = 2 ** (i - 1)
            mask = (1 << row_length) - 1
            reversed_row = row ^ mask
            row <<= row_length
            row += reversed_row
            
            current_length *= 2
            
            if current_length >= k:
                shift_length = current_length - k
                return (row >> shift_length) & 1
```
ACだが、実行時間4096ms, 使用メモリ228.70MBでまだまだ最低クラス

## Step.1
他の方々のPR、生成AIの意見を拝見して、修正する  

geminiに解くヒントをもらった  
> n行k番目のシンボルは, n-1行{(k+1)//2}番目をもとに決まります  
> kが奇数の時は, n-1行目のシンボルと一緒に、  
> kが偶数の時は, n-1行目のシンボルと反対になります

なるほど、律儀にn番目の`row`を作らなくても、(n-1)番目の`row`から、どの部分が影響しているのか  
というのをたどっていけば答えが出るのか  
実験結果を使って確認する  
`row`  
`1`　`0`  
`2`　`01`  
`3`　`0110`  
`4`　`01101001`  
`5`　`0110100110010110`   

`n=5, k=7`の時、  
5行7番目(`1`) = 4行4番目と同じ(`1`)  = 3行2番目(`0`) の反転  = 2行1番目(`1`) と同じ  = 1行1番目(`0`) の反転
確かに一致している  

自分の`row`の構成の捉え方が間違っていたわけではないと思うが、  
より良いアルゴリズムを求めるという点で言えば最適ではなかった  
真面目に列を作っていったらそりゃ時間かかるよね  

コードに起こしてみる
### 書いたコード 3
```python
class Solution:
    def kthGrammar(self, n: int, k: int) -> int:
        row = n
        number = k
        is_reverse = False

        while row > 1:
            if number % 2 == 0:
                is_reverse = not is_reverse
            number = (number + 1) // 2            
            row -= 1
        
        if is_reverse:
            return 1
        return 0
```
`n`の大きさだけwhileループが回り、ループ内処理は定数時間で行える、よってトータルで  
時間計算量:`O(n)`  
保持する値はすべて、大きさが定数のものなので、  
空間計算量:`O(n)`

せっかくだから、再帰でも書いてみる  
反転をフラグではなく、`1`から引くことで表現する  

### 書いたコード 4
```python
class Solution:
    def kthGrammar(self, n: int, k: int) -> int:
        if n == 1:
            return 0
        
        parent_symbol = self.kthGrammar(n - 1, (k + 1) // 2)

        if k % 2 == 0:
            return 1 - parent_symbol
        return parent_symbol
```
