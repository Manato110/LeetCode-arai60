# Step.0　まずは参考文献なしに
(冒頭の下り、AtCoderの問題みたいだな...)と思いつつ、解いていく  
すぐに思いついたアイデアは↓のような感じ  
 - 素朴にリストをソートしつつ、追加要素があれば追加し昇順ソート  
 - k番目に大きい要素 = 昇順ソートで後ろからk番目の要素　を返せばよい  

実際に書いたのが次のコード
```python
class KthLargest:

    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.nums = nums

    def add(self, val: int) -> int:
        self.nums.append(val)
        self.nums.sort()
        return self.nums[-self.k]
        
# Your KthLargest object will be instantiated and called as such:
# obj = KthLargest(k, nums)
# param_1 = obj.add(val)
```
しかし、このコードでは元の入力リスト`nums`自体に要素を追加しているという問題がある...  
sorted()関数なら元データを変更せず新たにソートしたリストを作れるが、  
sort()関数は元のリストそのものを書き換えてソートしてしまう(https://ai-kenkyujo.com/programming/language/python/sort/)  
&nbsp;  
けど別でリストを用意してもローカル変数になってしまうから保持できないし、  
クラスの定義的にadd関数内でwhile文を使って処理することもできないということで、  
この段階では解決できず  
&nbsp;  
時間計算量:`O(NlogN)`
- `__init__`では値の代入をしているだけなので`O(1)`  
- `add`では、`append`と`return`部分は要素追加、インデックス参照なので`O(1)`  
- `sort`関数は`O(NlogN)`で動く  
よって、全体で`O(NlogN)`

空間計算量:`O(N)`  
使用する空間は高々入力の要素分なので、入力の長さに比例

geminiにヒントをもらう  
上位k番目の要素が知りたいのだから、保持するのも上位k番目までで十分

これに気づけなかったのが悔しい...！  
&nbsp;  
また、ヒープ`heap`を使うことも提案された（見返したら、この問題はもともとヒープを想定されていた）  
ヒープをちゃんと使ったことがなかったので、試しでコードを書いてみる  
qiitaを参考に書きました(https://qiita.com/Midori_M/items/60fda736553478774f35)  
&nbsp;  
実際に書いたのが次のコード
```python
class KthLargest:

    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.topk = list(nums)
        heapq.heapify(self.topk)    # heap構造化
        if len(self.topk) > k:      # 上位k個だけ取り出す
            self.topk = self.topk[-k:]

    def add(self, val: int) -> int:
        # 要素がk未満なら昇順で追加
        if len(self.topk) < self.k:
            heapq.heappush(self.topk, val)
        
        # kthより大きいなら入れ替え
        elif val > self.topk[0]:
            heapq.heapreplace(self.topk, val) 

        return self.topk[0]
        
# Your KthLargest object will be instantiated and called as such:
# obj = KthLargest(k, nums)
# param_1 = obj.add(val)
```
実行してみるとテストケースで10/12  
geminiに原因を聞くと、  
```
heapq.heapify() を実行した後の self.topk は、「最小値が [0] にある」というルールは守っていますが、
リスト全体が小さい順に並んでいるわけではありません。
```  
とのこと  
どうやら、ヒープ化したリストは昇順に並んでいるわけではないらしい  
ということで、ヒープ構造の状態で要素がk個になるまで小さい要素から取り出すように修正  
&nbsp;  
修正前  
```python
if len(self.topk) > k:      # 上位k個だけ取り出す
  self.topk = self.topk[-k:]
```
修正後   
```python
while len(self.topk) > k:      # 上位k個だけ取り出す
  heapq.heappop(self.topk)
```
毎回1つずつ取り出すわけだし、while文で毎回長さを確認するのは無駄だと感じるが、  
必要な要素削除回数を求めて、それをfor文で回して...とするのとどちらが良いのかわからず...  
一旦、両方試してみることにした  
for文の方は次の感じ
```python
if len(self.topk) > k:
left_time = len(self.topk) - k # 必要な残り要素削除回数
for i in range(left_time)     # 上位k個以外を削除
  heapq.heappop(self.topk)
```
一旦、while文の方で全体コードを書く
修正後の全体コード
```python
class KthLargest:

    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.topk = list(nums)
        heapq.heapify(self.topk)    # heap構造化
        while len(self.topk) > k:      # 上位k個だけ取り出す
            heapq.heappop(self.topk)

    def add(self, val: int) -> int:
        # 要素がk未満なら昇順で追加
        if len(self.topk) < self.k:
            heapq.heappush(self.topk, val)
        
        # kthより大きいなら入れ替え
        elif val > self.topk[0]:
            heapq.heapreplace(self.topk, val) 

        return self.topk[0]
        
# Your KthLargest object will be instantiated and called as such:
# obj = KthLargest(k, nums)
# param_1 = obj.add(val)
```
while版とfor版両方でテストしたときの比較が次の通り  
while版  ：Runtime:`8ms`,  Memory:`25.80`    
for版    ：Runtime:`11ms`, Memory:`25.63`   
総合的に見たら、whileの方が良さそう  
毎回whileの条件文で長さ調べるのは無駄だしどうなんだろと思っていたが、  
長さ調べるのはそんなに大変じゃないのか、for版の方がかえって回りくどいことをしていたということか
