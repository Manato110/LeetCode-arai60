## Step.0
まずは自力で解く  
昇順ソート済みリスト`nums`に`target`を昇順となるように挿入するときの位置をO(logn)で求める  

以前扱った`bisect`と考えていることがかなり近いように思える  
前から要素を一つずつみていこうとしたら、最悪の場合リストの要素すべてを見る必要があり、O(n)になってしまう  

そこで、中央値を見て`target`と比較し、中央値より前の部分をみるか後の部分を見るか判断する  
これを繰り返せば、操作すべきリストの長さを毎回半分にすることが出来て、O(logn)になる  
というか、これが二分探索の考えそのものである  

少し気を付けるべきと思ったのが、`target`と同じ値がいくつも並んでいるようなリストの時の見方  
中央値 <= `target`なら前の部分、中央値 > `target`なら後ろの部分にしてあげれば良さそう  

とか思っていたら、入力リストの値は全て異なることが書いてあった  
`nums contains distinct values sorted in ascending order.`  
問題の解き方ばかり先に考えて、制約を見逃すのは本当にまずい...  
制約次第でどの変数に一番気を付けるべきかが変わったりするから  
気を付けよう  

コードに起こしてみる  

### 書いたコード  
```
class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        left = 0
        right = len(nums)

        while left < right:
            middle = (left + right) // 2
            middle_val = nums[middle]

            if middle_val < target:
                left = middle + 1
            else:
                right = middle
        
        return left
```
AC  
後から気づいたが、`middle_val`を1回しか使っていないから、ここの変数を設定する必要ないな  
たびたびこういうことをしてしまう...  
行き当たりばったりになっているというか、先を予測してコードを書くことが出来ていない  

まあ、以前問題解くときに`bisect`を調べて、中身を自身でも実装することをしていたので、苦ではなかった  
`bisect_left`と`bisect_right`で、同じ値が複数並んでいる部分の挿入位置が左側か右側かで分かれるが、それくらい  
例えば、`nums = [1,1,1,1]`、`target = 1`という場合で、  
`bisect_left`ならOutputは`0`、`bisect_right`なら`4`になる  
今回のコードは`bisect_left`側  

時間計算量；O(logn)　前述の通り、正確にはlogの底は2となる  
空間計算量：O(1)　保持する値は、`left`、`right`、`median`、`median_index`のみであり、これは入力の長さに依らない
