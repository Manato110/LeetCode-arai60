## Step.0
まずは自力で解く  
subarray..ということは部分列か  
最近Atcoderで部分列を扱う問題をやったから、その経験を活かせそう  
&nbsp;  
要素は`-1000 < nums[i] < 1000`だから負の値も取り得る　⇒　すべての部分列のパターンを見たいが、その時間があるのか...？  
要素数は`1 <= nums.length <= 2 * 104`だから、部分列として考えられるのは最大で`(2 * 104)(2 * 104 + 1) // 2 ≒ 2 * 207`  
`nums.length`があまりに大きいと間に合わない  
&nbsp;  
前にsubarrayを扱ったときは、動的計画法を用いていた  
例えば先頭から`l`番目までの和を`dp[l]`としてメモ化したら、  
入力配列の`i`番目から`j`番目まで`(i < j)`の部分列の和は`dp[j] - dp[i]`  
これだと`i`と`j`で二重の`for`文を書くことになり`O(N^2)`になりそうだが、毎回和を取るよりは早いのではなかろうか  
&nbsp;  
`dp`より`sum_table`の方が和をメモ化しているとわかりやすいか  
&nbsp;  
ということで次のような解法に至った  

 - 入力配列`nums`の`0`番目から`l`番目までの要素の和を`sum_table[l]`とメモする
 - 2重の`for`文で入力配列の`i`番目から`j`番目まで`(i < j)`の和`sum_table[j] - sum_table[i]`を求め、  
   `k`に一致したら`count`を`1`増やす  
 - 最後に`count`を出力

### 書いたコード1
```python
class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        sum_table = []
        total = 0
        for l in range(len(nums)):
            total += nums[l]
            sum_table.append(total)
        
        count = 0
        for i in range(len(nums)):
            for j in range(i + 1, len(nums)):
                if sum_table[j] - sum_table[i] == k:
                    count += 1
        
        return count
```
`WA`だった  
少し考えて、今のコードだと`sum_table[i]`, `sum_table[j]`の両方に`0`番目の要素が含まれているため、  
先頭を含んだ部分列を考慮できていないということに気づいた  
&nbsp;  
少し修正して、`sum_table`の`0`番目を「まだ何も足していない」という意味で`0`として  
一つずつずらすことで、帳尻合わせをおこなった  

### 書いたコード
```python
class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        sum_table = [0]
        total = 0
        for l in range(len(nums)):
            total += nums[l]
            sum_table.append(total)
        
        count = 0
        for i in range(len(nums) + 1):
            for j in range(i + 1, len(nums) + 1):
                if sum_table[j] - sum_table[i] == k:
                    count += 1
        
        return count
```
`testcase`では`AC`だったが、`submit`の結果ではほとんど`TLE`  
やっぱり二重ループは思いつきやすいけど時間がかかる  
&nbsp;  
時間計算量：`O(N^2)` 2重の`for`文のところで、トータル`N ^ 2 / 2`回の走査になる  
空間計算量：`O(N)`

## Step.1
良い解法が思いつかなかったので、他の方々のPR・Geminiを参考にしつつ修正していく  
Geminiに聞いて内容を自分的に解釈すると、大きく分けて2つの改善点がある  
1. リストではなく辞書(`defaultdict`)を使うことで、`sum_table`の参照を`O(N)`から`O(1)`に高速化できる
2. `sum_table[j] - sum_table[i] == k`を  
   `sum_table[j] - k == sum_table[i]`と読み替える  
   つまり、先頭から`j`番目までの和から`k`引いたものが、辞書のなかに存在  
   (今までに見たことがある和の値になっている)とする  
   &nbsp;  
   これなら、`j`だけを動かせばよくなるから、`O(N)`にできる   

改善点をもとに修正を加える  
&nbsp;  
辞書`sum_table`には、和の値を`Key`、その出現回数を`Value`として保存する  
例えば、`j`番目の要素までの和から`k`だけ引いた値が、これまでに2回登場していたのなら、  
和が`k`、終わりが`j`番目となるような足し始めの場所が2か所存在するということだから、 
これで和が`k`になる部分列の個数のカウント`count`を2増やせる  
&nbsp;  
コード2のときと同じく、何も足していない状態として`0`を辞書に入れる必要があるのは注意  
(足し始めが`0`番目の要素の場合を考えられるようにするため)

### 書いたコード3
```python
class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        sum_table = defaultdict(int)
        sum_table[0] = 1
        total = 0
        count = 0

        for num in nums:
            total += num
            target = total - k
            if target in sum_table:
                count += sum_table[target]
            sum_table[total] += 1
        
        return count
```
無事AC  
`sum_table[j] - sum_table[i] == k`を`sum_table[j] - k == sum_table[i]`と読み替える発想は出てこなかった...！  
いい勉強になりました  
時間計算量：`O(N)`  
空間計算量：`O(N)`
