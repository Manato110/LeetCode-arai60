## Step.0
まずは自力で解く  
問題の理解から  

Given an array of distinct integers candidates and a target integer target,   
return a list of all unique combinations of candidates where the chosen numbers sum to target.   
You may return the combinations in any order.  

The same number may be chosen from candidates an unlimited number of times.   
Two combinations are unique if the frequency of at least one of the chosen numbers is different.  

The test cases are generated such that the number of unique combinations that sum up to target is less than 150 combinations for the given input.  

```python
Example 1:
Input: candidates = [2,3,6,7], target = 7
Output: [[2,2,3],[7]]
Explanation:
2 and 3 are candidates, and 2 + 2 + 3 = 7. Note that 2 can be used multiple times.
7 is a candidate, and 7 = 7.
These are the only two combinations.

Example 2:
Input: candidates = [2,3,5], target = 8
Output: [[2,2,2,2],[2,3,3],[3,5]]

Example 3:
Input: candidates = [2], target = 1
Output: []
 

Constraints:
1 <= candidates.length <= 30
2 <= candidates[i] <= 40
All elements of candidates are distinct.
1 <= target <= 40
```

数字の集合`candidates`とターゲットとなる数字`target`が与えられる  
`candidates`の数字を無制限に使用して、総和が`target`となる組み合わせを重複なく全て出力する  
順序が並び替えられた組み合わせは同一のものとして扱う  

問題設定で、そのような組み合わせは150個以下であることが保証されている  
だいぶメタいが、個数が150個と少ないので、全部素直に求めていって大丈夫そう  

前問で学んだバックトラッキングの考えを使いたい  
つまり、考えられる組み合わせを見ていく中で、どう頑張っても総和が`target`にならないと判断できるときは  
撤退する、(剪定・枝刈りのイメージ)  

再帰 or DFS or BFSで考えていきたい  
保持する状態としては、まだ総和が`target`未満の組み合わせ`partial_combination`と、  
その総和`total`またはあといくつ必要かを表す残り`complement = target - total`の情報  
毎回総和を一から計算するのは時間がもったいないから、ここは総和に関する情報も保持したほうが良いと考える  
`total`か`complement`かは、正直どっちでも処理時間は変わりないと思う  
問題の印象として総和として積み上げていくイメージの方が強かったので、前者でやってみる  

もう一つ、組み合わせの中で最も`candidates`でのインデックスが大きかったものインデックスを保持したい  
新たな組み合わせを検討する段階で、それより大きいインデックスの要素しか追加できないというようにしたら  
最終的に得られる組み合わせについて重複を避けられる  
例えば、example 1をもとに考えると、`partial_combination = [3]`の時には、追加検討できる要素は`3, 5`のみとなる  
これにより、`[3, 5]`と`[5, 3]`のように、順序が並び替えられただけの組み合わせについて検討する手間が省ける  
(うまく言語化できていない気がする...)  

### DFS(BFS)で解く方法のアイデア  
スタック(orキュー)から`partial_combination`・`total`・`index`を受け取る  
 - `num`と`total`の和が`target`と等しくなるなら、目的となる組み合わせといえるので、  
   最後に出力するリストに組み合わせを追加  
 - `num`と`total`の和が`target`より大きくなるなら、そこから先はどう頑張っても`target`と等しくなることはないから、  
   打ち切る    
 - `num`と`total`の和が`target`未満なら...  
   - `candidates`の要素を`index`以上のものから順に取り出して検討  
   - `partial_combinaton`に`num`を追加したものと`total + num`を新たにスタックに格納  

上を書いて気づいたが、今回`candidates`が全て正(`2`以上)という制約があるから上のようにできるが、  
もし負の要素もあるのなら、組み合わせの総和が`target`より大きくなる場合についても  
後に`target`と等しくなる可能性があるので、枝刈りしないということになるか  

要素の重複がありなので、`n = candidates.length`とすると、nに依存して組み合わせ方が増加する  
ということで、DFS(or再帰)の方がメモリ効率が良くなると判断  

計算量をきちんと求めるのがちょっと面倒  
`candidates`の最小値を`m`、`target`を`t`と置く  
探索の木を想像すると、木の深さが最大となるのは、採択する要素が毎回`m`の時であるから、深さは最大で`n/m`  
各探索地点となるノードから最大で`n`本の枝を考えられる、よってノードの個数は`n ^ (n/m)`  
各ノードに対する処理は、`partial_combination + [num]`で新しいリストを作る部分が支配的で、これの長さは`O(n/m)`  
よって、全体では、時間計算量`O(n/m) * O(n ^ (n/m)) = O((n/m) * n ^ (n/m))`  
空間計算量は、`n`通り考えられる枝について、スタックで深さ`n/m`まで一度に積まれるのが最大で、全部で`O(n^2 / m)`  
各組み合わせの長さは`O(n/m)`なので、全体では`O(n^2 / m) * O(n/m) = O(n^3 / m^2)`  

BFSで記述した場合の空間計算量については、キューに積まれるのは、深さが`n/m`の時が最大で、全部で`O(n ^ (n/m))`個  
したがって、全体では`O(n/m) * O(n ^ (n/m)) = O((n/m) * n ^ (n/m))`  
この結果からも、DFSの方が空間計算量が優れていることが分かる  

コードを書く  
### 書いたコード 1 (DFS)
```python
class Solution:
    def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]:
        combinations = []
        frontier = [([], 0, 0)]

        while frontier:
            partial_combination, total, start_index = frontier.pop()
            if total == target:
                combinations.append(partial_combination)
                continue
            
            if total > target:
                continue
            
            for index in range(start_index, len(candidates)):
                num = candidates[index]
                frontier.append((partial_combination + [num], total + num, index))

        return combinations
```

### 書いたコード 2 (BFS)
```python
from collections import deque


class Solution:
    def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]:
        combinations = []
        frontier = deque([([], 0, 0)])

        while frontier:
            partial_combination, total, start_index = frontier.popleft()
            if total == target:
                combinations.append(partial_combination)
                continue
            
            if total > target:
                continue
            
            for index in range(start_index, len(candidates)):
                num = candidates[index]
                frontier.append((partial_combination + [num], total + num, index))

        return combinations
```

### 書いたコード 3 (recursion)
```python
class Solution:
    def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]:
        combinations = []
        partial_combination = []

        def backtrack(total: int, start_index: int):
            if total == target:
                combinations.append(partial_combination.copy())
                return
            
            if total > target:
                return
            
            for index in range(start_index, len(candidates)):
                num = candidates[index]
                partial_combination.append(num)
                backtrack(total + num, index)
                partial_combination.pop()

        backtrack(0, 0)
        return combinations
```
