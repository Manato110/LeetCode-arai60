## Step.0
まずは自力で解く  
問題の理解から  

Given an array of meeting time interval objects consisting of start and end times   
`[[start_1,end_1],[start_2,end_2],...] (start_i < end_i)`,   
determine if a person could add all meetings to their schedule without any conflicts.   
The intervals may be provided in any order.  
Note: (0,8),(8,10) is not considered a conflict at 8  

```python
Example 1:
Input: intervals = [(0,30),(5,10),(15,20)]
Output: false

Explanation:
(0,30) and (5,10) will conflict
(0,30) and (15,20) will conflict

Example 2:
Input: intervals = [(5,8),(9,15)]
Output: true

Constraints:
0 <= intervals.length <= 500
0 <= intervals[i].start < intervals[i].end <= 1,000,000
```
複数の会議時間スケジュールが開始と終了の時刻のペア`start`・`end`のリストで渡されて、  
会議の時間が被るところがないかを調べる  
被らないなら`True`、被るなら`False`を返す  

`The intervals may be provided in any order.`とあるので、  
`intervals`を`start`が昇順となるように先に並び替えた方が判定するのに良さそう  

被るところが一か所でもあったらアウト  
なので、直前の会議の時間と被りがないかを調べていけば大丈夫    

`start`を基準に並び替えた後に、`intervals`のペア要素を取り出しながら検証する  
並び替えた後の`intervals`について、  
`invervals[i].start < intervals[i - 1].end`となってしまった場合、  
被りが発生しているという事なので、`False`を返して終了  

`False`判定されることなくfor文の実行が終了したら、時間被りがないという事なので、`True`を返す  

これで、最初の`intervals`のソートに`O(nlogn)`、判定部分ですべての要素を見るのに`O(n)`かかるので、  
全体では時間計算量`O(nlogn)`  
空間計算量としては、入力を破壊しないために`sorted`でコピーを作ってソートをするのであれば、`O(n)`  

実行時間としては、`n`が最大500なので、ソートで大体`500 * log500 ≒ 500 * log(1024/2) = 4500`ステップくらい  
for文での処理で、一度も`False`判定されないときに一番時間がかかり、  
大体1ループ2ステップほどで全体なら`2 * 500 = 1000`ステップ  
よって合計`4500 + 1000 = 5500`ステップのため、pythonは`10^7 steps/s`なので、`0.55ms`くらいの見積もり  

特にひねりもない解法だが、見積もり的には良いんじゃないかな    
コードに起こす  

### 書いたコード 1
```python
"""
Definition of Interval:
class Interval(object):
    def __init__(self, start, end):
        self.start = start
        self.end = end
"""

class Solution:
    def canAttendMeetings(self, intervals: List[Interval]) -> bool:
        sorted_intervals = sorted(intervals, key=lambda x: x.start)

        for i in range(1, len(sorted_intervals)):
            if sorted_intervals[i].start < sorted_intervals[i - 1].end:
                return False
        
        return True
```
`AC`だったが、実行時間が大体30~40msほどで、見積もりとだいぶ乖離がある  
こうなった理由を考えてみたが、思いつかず...   

ここから短くするとなると、先ほどネックだった最初のソート部分を行わずに判定することができるのか...?  
今回登場する時間は`0`以上`1000000`以下という制約があるから、長さ`1000000`の数直線を用意して、  
時間範囲の重複がないならその時間の部分を塗りつぶすように当てはめていって、  
すでに塗りつぶされている所があったら`False`判定にする  
とか考えたけど、人間がこれをやることはできるが、プログラムでやると結局塗りつぶしに時間がかかり難しい  

思いつかなかったのでStep.1に移行

勉強として、書いてみる  
いもす法では、登場する値の下限から上限までの範囲の長さに等しい配列をまず用意する  
その後、`interavals`から順に`start`・`end`を取り出して、インデックスが`start`のところに+1、  
`end`のところに-1を足し合わせる  
最後に、配列を先頭から順に足し合わせていき、`2`以上となったら、`start`の間に`end`が入らない範囲が  
存在することになり、`False`と判定できる...というもの  
登場する値の上限を`m`としたら、時間計算量`O(n + m)`、空間計算量`O(m)`  

```python
def canAttendMeetings_ON(intervals: List[Interval]) -> bool:
    max_time = 100000 
    timeline = [0] * (max_time + 1)
    
    for interval in intervals:
        timeline[interval.start] += 1
        timeline[interval.end] -= 1
        
    num_in_meetings = 0
    for count in timeline:
        num_in_meetings += count
        if num_in_meetings > 1:
            return False
            
    return True
```
