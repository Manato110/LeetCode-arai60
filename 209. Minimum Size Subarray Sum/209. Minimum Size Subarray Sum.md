## Step.0
まずは自力で解く  
問題の理解から  

```
Descriptions  
Given an array of positive integers nums and a positive integer target,
return the minimal length of a subarray whose sum is greater than or equal to target.   
If there is no such subarray, return 0 instead.


Example 1:
Input: target = 7, nums = [2,3,1,2,4,3]
Output: 2
Explanation: The subarray [4,3] has the minimal length under the problem constraint.

Example 2:
Input: target = 4, nums = [1,4,4]
Output: 1

Example 3:
Input: target = 11, nums = [1,1,1,1,1,1,1,1]
Output: 0


Constraints:
1 <= target <= 10^9
1 <= nums.length <= 10^5
1 <= nums[i] <= 10^4
 

Follow up: If you have figured out the O(n) solution,
try coding another solution of which the time complexity is O(n log(n)).
```
ターゲットの数字`target`と数字の列`nums`が渡される  
`nums`の連続部分列で、総和が`target`以上となるモノのうち、長さが最小のものの長さを返す  
そのような連続部分列が存在しないなら、`0`を返す  

連続部分列を考える問題とスライディングウィンドウの相性が良さそうな感触  
連続部分列の左端、右端のインデックスを`left`・`right`として保持して、  
条件：「総和が`target`以上」を満たすところを探していく  
条件を満たしていたら、連続部分列の長さ`right - left + 1`を計算して、最小値を更新できるなら更新  

条件を満たしているかの判定について、  
 - 今の`left`・`right`で定まる連続部分列の総和`subseqence_sum`が`target`未満の場合、
   - `right`をインクリメントして、条件チェックする、条件を満たすまでインクリメントされる  
 - 今の`left`・`right`で定まる連続部分列の総和が`target`以上の場合、
   - `left`を操作して、連続部分列の長さを短くできるかを試みる
   - `subsequence_sum - nums[left]`が`target`以上の時、左端の要素を連続部分列に入れなくても条件を満たす  
     `nums[left]`の分だけ総和から引いて、`left`をインクリメント

`right`を`0`から`len(nums)-1`まで動かす、for文で条件を判定し、条件を満たすときの長さを都度求めていく感じで行けそう  

時間計算量は、`n=len(nums)`として、配列の長さに比例する分だけ`left`・`right`を動かすことが考えられるから、`O(n)`  
空間計算量は、値を保持するのはどれも定数であり、入力の長さに比例しない、よって`O(1)`  

コードに起こしてみる  
### 書いたコード 1
```python
class Solution:
    def minSubArrayLen(self, target: int, nums: List[int]) -> int:
        left = 0
        min_subsequence_length = float('inf')
        subsequence_sum = 0

        for right in range(len(nums)):
            subsequence_sum += nums[right]

            if subsequence_sum >= target:
                while subsequence_sum - nums[left] >= target:
                    subsequence_sum -= nums[left]
                    left += 1
                min_subsequence_length = min(min_subsequence_length, right - left + 1)
        
        if min_subsequence_length == float('inf'):
            return 0
        return min_subsequence_length
```
`AC`  

follow upで`O(nlogn)`の解法について言及されていたので考えてみる  

配列に対して`O(logn)`でできる操作と言ったら、`max`・`min`関数で最大・最小の要素を求める、二分探索..etc  
今回、入力の要素はすべて正なので、累積和`prefix_sum`は単調増加する  
インデックス`left`から`right`までの連続部分列の総和は、`right`までの累積和から`left`までの累積和の減算で求められる  

`prefix_sum[right] - prefix_sum[left] >= target`となるかつ、  
`right - left`が最小となる`right`、`left`を二分探索でどうにか求められないかな...  

ちょっと言い換えて...  
`left`を固定し、`prefix_sum[right] >= prefix_sum[left] + target`を満たす最小の`right`を二分探索で求める  
二分探索は`bisect`を使おう  
`right == len(prefix_sums)`となるとき注意が必要、  
これは`left`を左端としたときに、どう頑張っても総和が`target`以上にならないということと同義なので、  
この場合は何もしない  

`left`を`0`から`len(nums) - 1`まですべてで行えば、  
時間計算量`O(logn)`の操作を`n`回行うことになるから、合計`O(nlogn)`になる  
空間計算量は、累積和のリストを作る必要があり、`O(n)`  

コードを書いてみる  
```python
import bisect

class Solution:
    def minSubArrayLen(self, target: int, nums: List[int]) -> int:
        prefix_sums = [0] * (len(nums) + 1)
        for i in range(len(nums)):
            prefix_sums[i + 1] = prefix_sums[i] + nums[i]
        
        min_subsequence_length = float('inf')
        for left in range(len(nums)):
            target_prefix_sum = prefix_sums[left] + target
            right = bisect.bisect_left(prefix_sums, target_prefix_sum) 
            if right < len(prefix_sums):
                min_subsequence_length = min(min_subsequence_length, right - left)

        if min_subsequence_length == float('inf'):
            return 0
        return min_subsequence_length
```
