## Step.0
まず、問題の理解から  
&nbsp; 
`Intersection`とは？⇒
```
The intersection of two arrays is defined as the set of elements that are present in both arrays.
```
二つのリストがあったときに、両方のリストに存在する要素をまとめたら良い  
すぐにできそうと思いついた解法を2つ思いついた  
&nbsp;  
アイデア1  
 - 答えとなる空セット`result`を用意 (重複部分は考えないのでリストではなくセットで実装する)
 - `nums1`,`nums2`のうち、長さが短い方を基準にする
 - 要素を順番に見ていって、`result`にない要素かつ、もう片方のリストにその要素があれば`result`に格納
 - 最後に`result`を出力
&nbsp;  

アイデア2  
 - 共通となる要素を取る = 二つの集合の積集合を取ることと同じ  
 - なので、`nums1`, `nums2`それぞれをリストからセットにして重複部分を削除する  
 - 二つのセットの積集合を出力する  
&nbsp;

両方書いてみる  
書く前の印象としては、(後に思いついた)アイデア2の方が、スマートに解けていそうかな？という感じ

### 書いたコード1
```python
class Solution:
    def intersection(self, nums1: List[int], nums2: List[int]) -> List[int]:
        nums1_set = set(nums1)
        nums2_set = set(nums2)

        large_set = nums1_set if len(nums1_set) > len(nums2_set) else nums2_set
        short_set = nums2_set if len(nums1_set) > len(nums2_set) else nums1_set

        result = []
        for num in short_set:
            if num in large_set:
                result.append(num)
        
        return result
```
書いてる途中から、`set`の長さを基準を決めない方が、コードがすっきりしそうと思ったが、  
set()の検索に必要な時間計算量が`O(1)`であることから、やっぱり必要と思い直す  
ACでした  
 - 時間計算量:`O(n1+n2)` `set`にしたときに、要素が少ない方の要素数に比例  
 - 空間計算量:`O(n1+n2)` それぞれの入力リストの長さに比例  

続いて、アイデア2の方で書いてみる  
積集合は`&`演算子で記述できる

### 書いたコード2
```python
class Solution:
    def intersection(self, nums1: List[int], nums2: List[int]) -> List[int]:
        return list(set(nums1) & set(nums2))
```
明らかにコード1よりも簡潔で見やすいし、なにより何をやっているかが分かりやすいという印象を受ける  
(なぜこちらを真っ先におもいつかなかったのか... )
 - 時間計算量:`O(n1+n2)` それぞれのリストを`set`にするときに、要素数に比例  
 - 空間計算量:`O(n1+n2)` それぞれの入力リストの長さに比例  

オーダーで見ると同じだが、コード1では`for`文でループを使っているのに対して、コード2は使っていない  
実行する命令が少ないコード2の方が、実行時間も短くなるだろう  
と思ったが、提出したらどちらも`Runtime:0ms`だったので、誤差レベルなのかもしれない

### 書いたコード3
```python
class Solution:
    def intersection(self, nums1: List[int], nums2: List[int]) -> List[int]:
        large_nums, short_nums = (nums1, nums2) if len(nums1) > len(nums2) else (nums2, nums1)
        short_set = set(short_nums)
        return list(short_set.intersection(large_nums))
```

実行時間を見ると、コード2の時より長くなっていた  
両方のリストの長さが短いときは、コード2の方が良いのだろう  
片方のリストがとても大きく、片方のリストがとても小さいときにはコード3の方が良いコードといえるはず  
いろんなシチュエーションを考えてコードを書く視点が今まであまりなかったので、ためになった
