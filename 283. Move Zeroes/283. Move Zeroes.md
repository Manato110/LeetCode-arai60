## Step.0

問題の理解から  

Given an integer array nums, move all 0's to the end of it while maintaining the relative order of the non-zero elements.  
Note that you must do this in-place without making a copy of the array.  

Follow up: Could you minimize the total number of operations done?  
 
```python
Example 1:
Input: nums = [0,1,0,3,12]
Output: [1,3,12,0,0]

Example 2:
Input: nums = [0]
Output: [0]
 
Constraints:
1 <= nums.length <= 10^4
-2^31 <= nums[i] <= 2^31 - 1
 ```
整数が格納された入力リストについて、要素`0`を全て末尾に移動させて出力する  
入力のコピーを作成することはNGで、in-placeでおこなう  
returnはしなくて良いらしい  

plute-forceに考えるなら、先頭から要素を見ていって、`0`を見つけたら削除->末尾に追加を繰り返す...?  
とか考えたが、走査中のリストに対して要素の削除・追加をしたらインデックスがずれたりして、うまくいかない  
コピーを作成してokならやりようはあったが...  

あらかじめ`c = nums.count(0)`で数えておいて、`0`の削除と`c`個の`0`を末尾への追加をおこなうとか  
リストで指定要素の削除と追加は`remove`・`append`でできるが、  
`remove(0)`には、`0`の探索->`0`削除後にそれより後ろの要素を全て前に1つずらす  
という結構重たい処理(`O(n)`)  
なので、トータルで時間計算量`O(cn)`となる  
実行時間を考えると`n`が最大の10^4のとき、`c`を求めるのに10^4回、  
その後、`remove`で平均`10^4 / 2`個の要素を見た後に、平均`10^4 / 2`個の要素をずらすのと、  
`append`で`0`の追加で1回の処理、  
これを`c`回行うので、合計`10^4 + c * (10^4 + 1)`  
仮に`0`が全要素のうち半数を占めていたら、`10^4 + 10^4 / 2 * (10^4 + 1) ≒ 5 * 10^7`実行ステップ  
pythonでは`10^7`ステップ/秒なので、大体5sくらい  
やっぱり`remove`がボトルネックになるな

空間計算量は、`O(1)`

一応、書いてみる  
### 書いたコード 1
```python
class Solution:
    def moveZeroes(self, nums: List[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
        count_zero = nums.count(0)
        for i in range(count_zero):
            nums.remove(0)
            nums.append(0)
```

### 書いたコード 2
```python
class Solution:
    def moveZeroes(self, nums: List[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
        num_non_zero = 0
        for num in nums:
            if num != 0:
                nums[num_non_zero] = num
                num_non_zero += 1

        for i in range(num_non_zero, len(nums)):
            nums[i] = 0
```
`0`msで`AC`  

思い返せば、in-placeで実行するということは、かなり入力を破壊するような操作がメインとなる  
その中で、なるべく破壊しないようにする方法が、要素の交換で済ませる・破壊した個数のメモをする...といったところか  
そう考えたら、今回のようにポインタによる解法が思いつくのも、自然なのかもしれない  
in-placeで`remove`・`append`は結構注意が必要な操作という感覚になった  

まあ、今回のコードも非ゼロで上書きする操作をしていて、ちょっと心配  
途中で実行を止められるような事態になったときに、何か問題がないかと思った  
例えばマージソートとかだったら、in-placeに要素の交換のみだから、途中で実行が止まっても、  
別にソートが目的だから、途中で止められた入力列に対してもう一度ソートを考えたら問題ないけど、  
今回の場合はどうか  
`num_non_zero`、`num`が何だったのかが分かれば行けるのか  
でもなんか怖い...そもそも、実社会でin-placeにコードを書くときがどのような時なのかがよくわからない
